Picard Tag Mapping: Vorbis DISCNUMBER and TOTALDISCS

This article outlines how MusicBrainz Picard handles multi-disc tag mapping for audio formats utilizing Vorbis comments, such as FLAC and Ogg Vorbis. It details the internal variables Picard uses for disc positions, how they map directly to the DISCNUMBER and TOTALDISCS Vorbis fields, and how Picard processes alternative legacy tags during reading and writing operations.

Picard Internal Variables to Vorbis Comments

MusicBrainz Picard utilizes internal metadata variables wrapped in percent signs. When saving metadata to files using Vorbis comments, Picard maps these variables directly to specific field names:

  • %discnumber% maps to DISCNUMBER
  • %totaldiscs% maps to TOTALDISCS

Reading Behavior

When reading files with Vorbis comments, Picard parses existing fields into its internal variables using the following rules:

  • Disc Number: Picard reads the value of DISCNUMBER. If the tag contains a slash (e.g., 1/2), Picard extracts the first value as %discnumber% and the second value as %totaldiscs%.
  • Total Discs: Picard reads TOTALDISCS to populate %totaldiscs%. Picard also reads the alternative field DISCTOTAL for backward compatibility with older tagging schemes or other media management software.

Writing Behavior

When saving metadata back to Vorbis comments:

  • Picard writes the disc's index to DISCNUMBER as a single integer (e.g., 1).
  • Picard writes the total count of discs in the release to TOTALDISCS as a single integer (e.g., 2).
  • By default, Picard does not write combined strings (such as 1/2) into DISCNUMBER for Vorbis comments, adhering to the standard multi-field structure of the Vorbis comment specification.
