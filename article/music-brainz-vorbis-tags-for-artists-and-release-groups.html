MusicBrainz Vorbis Tags for Artists and Release Groups

MusicBrainz standardizes metadata for Vorbis comment containers—used in formats like FLAC, Ogg Vorbis, and Opus—by mapping structured database entities into specific, standardized key-value pairs. This article outlines how MusicBrainz formats and standardizes artist information, release group identifiers, and associated UUIDs to ensure consistent playback, organization, and scrobbling across digital audio software.

Vorbis Comment Architecture

Vorbis comments are case-insensitive, UTF-8 encoded KEY=Value pairs that support repeated keys for multiple values. Rather than embedding flattened or proprietary strings, MusicBrainz uses standardized tag names and persistent 128-bit UUIDs (MusicBrainz Identifiers, or MBIDs) to link audio files directly to canonical database entries.

Standardizing Artist Information

MusicBrainz categorizes artist metadata across track-level performers and album-level contributors, standardizing both human-readable strings and machine-readable identifiers:

  • ARTIST: Stores the localized artist credit as it appears on the specific release liner notes.
  • ARTISTSORT: Stores the alphabetical sort name of the track artist (for example, "Beatles, The" instead of "The Beatles").
  • MUSICBRAINZ_ARTISTID: Contains the MBID of the track artist. If multiple artists collaborate, MusicBrainz standardizes this by writing separate, repeated MUSICBRAINZ_ARTISTID tags for each individual artist entity rather than joining them with delimiters.
  • ALBUMARTIST: Stores the primary artist or collective credited for the overall release.
  • ALBUMARTISTSORT: Stores the standardized alphabetical sort order for the primary release artist.
  • MUSICBRAINZ_ALBUMARTISTID: Contains the MBID corresponding to the primary album artist entity, supporting multiple instances for collaborative albums.

Standardizing Release Group Metadata

In the MusicBrainz schema, a Release Group represents the abstract, conceptual project (such as the overarching album Abbey Road), while a Release represents a specific physical or digital issue (such as a 1987 UK CD or a 2019 US vinyl remaster). MusicBrainz standardizes release group classification using the following Vorbis comment keys:

  • MUSICBRAINZ_RELEASEGROUPID: Stores the unique MBID corresponding to the abstract release group. This allows media managers to group diverse pressings, reissues, and regional variants of the same core album under a single logical unit.
  • RELEASETYPE: Designates the release group category. MusicBrainz uses a hierarchical taxonomy including primary types (such as album, single, ep, broadcast, or other) and secondary types (such as compilation, soundtrack, live, remix, or dj-mix). When multiple types apply, standard taggers write multiple RELEASETYPE tags or format them as multi-value arrays according to the Vorbis specification.
  • MUSICBRAINZ_RELEASEGROUPTYPE: An alternative or historical field often mirrored alongside RELEASETYPE by taggers like MusicBrainz Picard to preserve backward compatibility with legacy media players.

Multi-Value Tag Execution

MusicBrainz adheres strictly to the native Vorbis specification by avoiding concatenated string separators like slashes or semicolons whenever native multi-field tagging is supported. For releases featuring guest performers or split-album releases, each contributing artist's identifier is written as a distinct, subsequent MUSICBRAINZ_ARTISTID entry. This guarantees programmatic parsers can resolve accurate entity relationships without relying on text-parsing heuristics.
