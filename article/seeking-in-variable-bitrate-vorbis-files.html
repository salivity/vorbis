Seeking in Variable Bitrate Vorbis Files

Seeking within a Variable Bitrate (VBR) Vorbis file relies on the structural metadata provided by its container—typically Ogg—combined with sample-level timestamps. Because VBR audio allocates varying amounts of data depending on the complexity of the sound, a specific byte offset does not correspond to a fixed duration of time. Decoders overcome this by calculating target sample counts, reading "granule positions" inside container page headers, and executing an optimized bisection search across the physical file to achieve fast, sample-accurate navigation.

The Role of Granule Position

Vorbis audio streams are divided into small packets packaged inside larger Ogg pages. Each Ogg page header contains a 64-bit integer known as the granulepos (granule position).

In a Vorbis stream, the granulepos represents the exact cumulative PCM sample count encoded up to the end of that specific page. Because the sample rate of the audio is constant (such as 44,100 Hz or 48,000 Hz), the precise playback timestamp of any page can be determined mathematically:

\[\text{Timestamp (seconds)} = \frac{\text{granulepos}}{\text{Sample Rate}}\]

Calculating the Target Sample

When a user requests a jump to a specific time, the playback engine converts that target time into an absolute sample index:

\[\text{Target Sample} = \text{Target Time (seconds)} \times \text{Sample Rate}\]

Once the target sample is determined, the decoder must locate the exact physical byte offset of the Ogg page containing that sample without reading the entire stream from the beginning.

The Bisection Search Process

To find the correct page efficiently across variable-density data, the decoder performs an iterative bisection (binary) search:

  1. Initial Boundary Estimation: The decoder knows the file's start offset (sample 0) and end offset (determined by reading the granulepos of the file’s final Ogg page). It estimates an initial byte position using linear interpolation based on the average bitrate.
  2. Page Header Inspection: The decoder seeks to the estimated byte offset, scans forward for the four-byte capture pattern (OggS) that marks an Ogg page, and reads the page’s granulepos.
  3. Range Narrowing:
    • If the page’s granulepos is lower than the target sample, the target lies further ahead in the file; the current position becomes the new lower boundary.
    • If the page’s granulepos is higher than the target, the current position becomes the new upper boundary.
  4. Convergence: The decoder repeats this interpolation and bisecting process until it isolates the specific Ogg page that spans the target sample range.

Window Overlap and Sample-Accurate Decoding

Finding the page is not the final step for Vorbis. Vorbis uses the Modified Discrete Cosine Transform (MDCT) with overlapping audio windows. To reconstruct any given audio sample accurately, the decoder requires the audio data from the packet immediately preceding it.

Therefore, the seeking engine backtracks slightly:

  • It locates the packet just before the target sample.
  • It decodes the overlapping MDCT window to prime the internal synthesis filter.
  • It discards any decoded samples prior to the requested target sample.

This discard-and-sync phase guarantees that the audio resumes immediately at the exact requested millisecond with zero digital clicks, pops, or synchronization drift.

Indexed Seeking Optimization

While standard bisection requires reading several page headers over disk or network I/O, modern media players and game engines often optimize this by building an in-memory seek table during the initial file scan or downloading an external index. When an index exists, the bisection search is performed instantaneously against an array of byte-to-sample pairs, allowing the read head to jump directly to the target Ogg page in a single operation.
