How to Format LYRICS Tags in Vorbis Files

This article explains how unsynchronized lyrics are stored and formatted in Vorbis files using the LYRICS and UNSYNCEDLYRICS Vorbis comment fields. It covers the structural requirements, text encoding, line break conventions, and tag naming standards across audio players and tagging software.

Vorbis Comment Basics

Metadata in Vorbis files (such as Ogg Vorbis and FLAC) is stored using the Vorbis comment specification. Unlike ID3 tags, Vorbis comments consist of simple FIELD_NAME=Value pairs.

  • Field Names: Field names are case-insensitive and restricted to printable ASCII characters (0x20 through 0x7D, excluding the equals sign =). By convention, field names are written in uppercase.
  • Field Values: Values are arbitrary byte sequences explicitly defined as UTF-8 text strings. Length is determined by a 32-bit integer prefix, meaning field values can contain any character, including line breaks, without breaking the parser.

LYRICS vs. UNSYNCEDLYRICS

There is no formal specification for lyrics in the original Xiph.Org Vorbis comment standard, but standard conventions have developed:

  • LYRICS: This is the most widely supported and recommended field name in the Vorbis comment ecosystem. Software such as Foobar2000, Kid3, and most modern media players use LYRICS as the default field for plain-text, unsynchronized lyrics.
  • UNSYNCEDLYRICS: This field name is derived from the ID3v2 USLT (Unsynchronized lyrics/text transcription) tag. Some tagging software (such as MusicBee or Mp3tag, depending on mapping settings) uses UNSYNCEDLYRICS to preserve parity when converting files from MP3 to Ogg Vorbis or FLAC.

For maximum compatibility across different software, LYRICS is preferred, though many modern audio players read both fields interchangeably.

Text Formatting and Line Breaks

Unsynchronized lyrics should be formatted as plain text:

  • Encoding: The text must be encoded in valid UTF-8. No byte order mark (BOM) is required.
  • Line Breaks: Standard line breaks—either LF (\n, common in Unix-like environments) or CRLF (\r\n, standard in Windows)—are permitted directly inside the field value.
  • Stanza Separation: Separate stanzas or verses using a blank line (double newline).
  • Timestamps: Unsynchronized lyrics should not include LRC-style timestamps (e.g., [00:12.34]). If timestamps are included, the field functions as synchronized lyrics, which is typically parsed differently.

Handling Language and Content Descriptors

In ID3v2 (USLT), unsynchronized lyrics contain separate sub-fields for language codes (e.g., eng) and content descriptors.

Vorbis comments do not natively support sub-fields within a single value. When mapping an ID3 USLT frame to a Vorbis comment:

  • Drop the language code and content descriptor entirely, storing only the raw lyric text in the LYRICS field.
  • Alternatively, if language tracking is required, store the language as a separate tag (such as LANGUAGE=eng) rather than prefixing it to the lyric string.

Example Format

Within the Vorbis comment metadata block, the raw entry is structured as follows:

LYRICS=First line of the song
Second line of the song

Third line after a stanza break
Fourth line of the song

Because the value is length-prefixed rather than null-terminated, line breaks are preserved exactly as written.
