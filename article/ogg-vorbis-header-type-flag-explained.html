Ogg Vorbis Header Type Flag Explained

The header type flag in an Ogg page containing Vorbis data is an 8-bit field located in the physical Ogg page header that signals the structural state of the bitstream. It defines whether the data payload on that specific page begins a new logical stream, terminates an existing stream, or continues a packet that was split across a page boundary. Understanding this flag is essential for demuxing and decoding Vorbis audio streams properly.

Structure and Location of the Flag

In an Ogg bitstream, data is organized into transport frames known as pages. The header type flag is the 6th byte (offset byte 5) of the standard 27-byte Ogg page header, positioned directly after the stream structure version byte. It is evaluated as a bitfield where only the lowest three bits are utilized; the remaining five bits are reserved and must remain zero.

Defined Bitmask Values

The header type flag uses three distinct bit flags to indicate the page's structural status:

  • 0x01 (Continuation Flag): Indicates that the first packet on this page is a continuation of an unfinished packet from the previous page. If this bit is unset (0), the first packet starts fresh on this page.
  • 0x02 (Beginning of Stream / BOS): Marks this page as the initial page of a logical bitstream. In an Ogg Vorbis file, the very first page containing the Vorbis identification header must have this bit set.
  • 0x04 (End of Stream / EOS): Marks this page as the final page of a logical bitstream. Once this page is processed, the decoder recognizes that no further Vorbis audio packets will arrive for this stream identifier.

When none of these conditions apply—such as during regular, unbroken Vorbis audio data playback in the middle of a track—the header type flag is set to 0x00.

Role in Vorbis Decoding

Vorbis codec data depends heavily on these flags to ensure packet continuity and correct initialization:

  1. Stream Identification: A Vorbis decoder looks for a page with the 0x02 (BOS) flag to detect the start of a stream and parse the initial setup packets (identification, comment, and setup headers).
  2. Packet Reassembly: Because Vorbis audio frames can exceed the maximum physical size of an Ogg page payload (approximately 65 KB), the 0x01 flag informs the demuxer that the initial segment must be appended to the uncompleted packet from the preceding page before being handed to the Vorbis synthesis layer.
  3. Playback Termination: The 0x04 (EOS) flag signals the end of the audio track, allowing the player to safely flush remaining buffers or transition to a chained stream.
