What Is the BOS Flag in a Vorbis Header Page?

The Beginning of Stream (BOS) flag is a fundamental marker within the Ogg encapsulation format used by Vorbis audio, signaling the absolute start of a logical bitstream. This article explains the technical purpose of the BOS flag, its exact location in an Ogg Vorbis page header, how decoders use it to initialize playback parameters, and its critical role in managing multiplexed and chained media streams.

Location and Structure of the BOS Flag

Vorbis audio streams are typically wrapped in the Ogg container format, which divides data into discrete chunks called pages. Every Ogg page begins with a 27-byte capture header containing metadata about the page.

Within this header, the fifth byte is designated as the "header type flag." This byte uses bitwise flags to indicate the page's position and continuity within the stream:

  • 0x01 (Continuation): The page continues a packet started on a previous page.
  • 0x02 (BOS - Beginning of Stream): This page is the initial page of a logical bitstream.
  • 0x04 (EOS - End of Stream): This page is the final page of a logical bitstream.

When bit 1 (mask 0x02) is set, the page is officially designated as the BOS page.

The Role of the BOS Page in Vorbis Decoding

A Vorbis bitstream requires three mandatory header packets before any audio data can be decoded: the identification header, the comment header, and the setup (codebook) header.

The page marked with the BOS flag must contain the Vorbis identification header. This packet delivers crucial metadata to the decoder, including:

  • The Vorbis audio version
  • The number of audio channels (e.g., mono, stereo, 5.1 surround)
  • The audio sample rate (e.g., 44.1 kHz, 48 kHz)
  • Bitrate limits (nominal, minimum, and maximum bitrates)
  • Framing and block size information

Because this identification packet resides on the BOS page, a decoder reading the stream can immediately allocate memory and configure the audio pipeline before encountering actual audio packets.

Stream Multiplexing and Identification

The Ogg container allows multiple media streams to be grouped together (multiplexed) into a single physical stream, such as combining Vorbis audio with Theora video. Each logical bitstream has a unique serial number assigned in the page header.

The BOS flag is critical for handling these configurations:

  1. Multiplexed Streams: At the beginning of a multiplexed file, an Ogg container will output a cluster of BOS pages—one for each distinct stream—before sending any audio or video data. Decoders read every initial BOS page to inventory all available tracks and associate each track with its unique bitstream serial number.
  2. Chained Streams: In continuous or concatenated streams (such as internet radio broadcasts), a new stream with different audio settings can follow immediately after an EOS (End of Stream) flag. The appearance of a new BOS flag alerts the decoder to re-initialize its settings for the new logical bitstream.

Decoder Validation and Error Prevention

Enforcing the BOS flag helps decoders prevent playback errors. If an audio decoder begins parsing an Ogg file from an arbitrary point (such as during an incomplete download or mid-stream network capture) and does not encounter a BOS flag on the first page it reads, it knows that essential setup headers are missing. The decoder can safely reject the stream or scan forward until it finds a valid initialization boundary, preventing corrupted audio output or application crashes.
