Container Format for Streaming Vorbis Over MPEG-DASH

Streaming the Vorbis audio codec over Dynamic Adaptive Streaming over HTTP (MPEG-DASH) requires the WebM container format. While standard MPEG-DASH implementations commonly deploy fragmented MP4 (ISOBMFF) for audio codecs like AAC, Vorbis streaming relies on the WebM container profile designed for DASH. This article explains why the WebM container is required, how it encapsulates Vorbis data, and how it integrates into DASH Media Presentation Description (MPD) manifests.

The WebM Container Format

To deliver Vorbis audio via MPEG-DASH, media engines use the WebM container format (a restricted subset of the Matroska/EBML specification). The standard ISO Base Media File Format (ISOBMFF/fMP4) lacks native, standardized commercial adoption for the Vorbis bitstream structure. As a result, the WebM Project introduced the WebM DASH profile to enable adaptive streaming of open codecs—pairing VP8/VP9 video with Vorbis or Opus audio.

When streaming Vorbis over DASH using WebM, the container is split into two primary components:

  • Initialization Segment: Contains the EBML header, segment information, and track headers. For Vorbis, this segment must include the codec private data, which carries the three required Vorbis setup header packets (identification, comments, and setup codebooks). Without this initialization data, decoders cannot parse the subsequent audio packets.
  • Media Segments: Composed of standard WebM Cluster elements containing sequential SimpleBlock structures. Each SimpleBlock holds raw Vorbis audio frames.

Integration in the DASH Manifest (MPD)

To inform adaptive streaming players (such as Shaka Player or Dash.js) of the stream format, the DASH MPD manifest explicitly defines the WebM container and the Vorbis codec within the audio representation elements:

  • MIME Type: audio/webm
  • Codecs Parameter: vorbis
  • Segment Templates: Segments can be referenced via $Number$ or $Time$ addressing, referencing standalone segment files or byte-range requests inside a single WebM file using an index segment (Cues).

By packaging Vorbis into segmented WebM files and declaring the audio/webm; codecs="vorbis" MIME type, DASH players can demux the clusters and decode the underlying audio stream adaptively.
