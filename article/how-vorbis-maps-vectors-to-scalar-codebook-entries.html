How Vorbis Maps Vectors to Scalar Codebook Entries

The Vorbis audio codec utilizes vector quantization (VQ) to compress multidimensional spectral data into compact, scalar codebook indices. This article details how continuous audio vectors are partitioned, matched to the nearest vector template within a predefined codebook, assigned an integer scalar index for entropy coding, and reconstructed using Vorbis lookup types.

Vector Grouping and Representation

During the encoding process, Vorbis groups consecutive residual spectral samples into multidimensional vectors of length \(N\) (the codebook dimension). Rather than quantizing each frequency coefficient independently, the encoder treats an array of \(N\) values as a single point in an \(N\)-dimensional space.

Each unique vector position in this space corresponds to a scalar index (ranging from \(0\) to \(M-1\), where \(M\) is the codebook size). The codebook serves as a shared lookup table between the encoder and decoder, mapping multi-sample shapes to discrete scalar identifiers.

The Search and Quantization Process

To map a multidimensional input vector \(\mathbf{x} = [x_0, x_1, \dots, x_{N-1}]\) to a single scalar entry:

  1. Distance Metric Evaluation: The encoder compares the input vector \(\mathbf{x}\) against all available vectors \(\mathbf{y}_i\) in the active codebook. This search typically minimizes the mean squared error (Euclidean distance) or a psychoacoustically weighted distortion metric.
  2. Index Selection: The index \(i\) corresponding to the vector \(\mathbf{y}_i\) with the lowest distortion is selected as the winning scalar symbol.
  3. Entropy Coding: The resulting scalar integer \(i\) is converted into a variable-length bit sequence using a Huffman prefix tree assigned to that specific codebook.

Decoding and Codebook Lookup Types

Once the decoder reads the variable-length bitstream, it recovers the scalar integer index \(i\). Vorbis defines two primary lookup mechanisms to map this scalar index back into an \(N\)-dimensional vector without storing massive uncompressed tables in memory:

Lookup Type 1: Algorithmic Lattice Construction

Lookup Type 1 avoids storing complete vectors by defining an implicit grid or lattice. The codebook specifies a base list of scalar quantization values.

To unpack the scalar index \(i\) into \(N\) vector components:

  • The scalar index is iteratively decomposed using base arithmetic (modulo and division operations) corresponding to the number of quant values per dimension.
  • The extracted sub-indices select values from the scalar value list.
  • If configured, a sequence-dependent delta is added to the values to establish monotonically increasing or decreasing trajectories (useful for spectral floor curves).

This approach allows high-dimensional codebooks to consume very little memory in the bitstream headers.

Lookup Type 2: Explicit Codebook Tables

Lookup Type 2 defines vectors explicitly. The codebook stores an explicit array of coordinates:

  • The scalar index \(i\) is directly multiplied by the dimension \(N\).
  • The decoder reads \(N\) consecutive values beginning at the offset \((i \times N)\) from the codebook value list.

Type 2 provides total freedom in vector point placement at the expense of requiring more data in the codebook setup header, making it well-suited for low-dimensional, highly irregular residual audio patterns.

Final Dequantization

After retrieving the raw quantized vector coordinates via Type 1 or Type 2 mappings, the decoder scales and offsets the values. Using the codebook's global minimum value, delta step size, and sequence flag parameters, the normalized integers are reconstructed into the floating-point spectral domain for final audio synthesis.
