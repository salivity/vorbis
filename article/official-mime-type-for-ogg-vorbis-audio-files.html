Official MIME Type for Ogg Vorbis Audio Files

The officially registered MIME type for Ogg Vorbis audio files is audio/ogg. This article outlines the official standard established by the Internet Engineering Task Force (IETF), explains the context behind its registration, and covers legacy types and best practices for server configuration when serving Ogg Vorbis media.

The Official Standard: RFC 5334

According to RFC 5334 (which updates RFC 3534), the official media type for an Ogg bitstream containing only audio content is audio/ogg.

Before this standard was finalized, Ogg files were categorized under the generic application/ogg MIME type. To improve how web browsers and operating systems handle media streams, the IETF split Ogg media types based on content:

  • audio/ogg: Specifically for audio-only streams, including Vorbis, FLAC, and Opus inside an Ogg container.
  • video/ogg: For streams containing video (such as Theora), which may also contain audio.
  • application/ogg: Retained as a fallback for multiplexed or non-audio/video media.

Using the Codecs Parameter

When serving Ogg Vorbis content over HTTP—especially for HTML5 <audio> playback—you can provide an optional codecs parameter to explicitly inform the client of the underlying encoding without requiring the browser to download and inspect the stream header:

Content-Type: audio/ogg; codecs=vorbis

Legacy and Unofficial MIME Types

Prior to the formal adoption of audio/ogg, several non-standard or older types were in circulation:

  • application/ogg: The original RFC 3534 specification. While still recognized by many systems, modern web standards require audio/ogg for audio files.
  • audio/x-vorbis: An unofficial, vendor-prefixed type used before standardization.
  • audio/vorbis: A proposed type that was ultimately superseded by container-based naming.

Web Server Configuration

To ensure web browsers handle .ogg or .oga Vorbis files correctly, web servers should be configured to return the audio/ogg header.

  • Apache (.htaccess or mime.types):

    AddType audio/ogg .ogg .oga

  • NGINX (mime.types):

    types {
    audio/ogg ogg oga;
}
