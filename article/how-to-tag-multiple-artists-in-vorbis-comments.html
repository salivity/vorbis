How to Tag Multiple Artists in Vorbis Comments

This article explains how multi-artist collaborations are handled within the standard Vorbis comment metadata framework used by formats like FLAC, Ogg Vorbis, and Opus. It covers the official specification's use of repeated fields, conventions for distinguishing main and guest artists, real-world software compatibility challenges, and best practices for cataloging collaborative tracks.

The Standard Approach: Repeated Field Keys

The official Vorbis comment specification handles multi-value metadata, including multiple artists, by repeating the field key rather than combining multiple names into a single entry with delimiters.

In a compliant metadata block, a collaboration between two artists is written as two distinct fields:

ARTIST=Alice
ARTIST=Bob

Because Vorbis comments are structured as a simple list of NAME=value pairs, the specification allows any key to appear more than once. Media players and taggers that strictly follow the specification parse each ARTIST tag individually, adding the track to both Alice's and Bob's discographies without confusing their names as a single entity.

Primary vs. Contributing Artists

Collaborations often involve different levels of contribution, such as guest features, producers, or primary album artists. Standard Vorbis comments accommodate these relationships using dedicated complementary fields:

  • ALBUMARTIST: Defines the main artist or band responsible for the overall release. If Alice releases an album featuring Bob on one track, ALBUMARTIST=Alice ensures the album stays unified in library views, while the track itself retains both ARTIST=Alice and ARTIST=Bob.
  • PERFORMER: Used when specific roles need delineation, such as PERFORMER=Bob (vocals) or PERFORMER=Alice (guitar).
  • COMPOSER: Applied similarly for collaborative songwriting, repeating the key for each individual: COMPOSER=Alice and COMPOSER=Bob.

Delimiters and Real-World Software Workarounds

While repeated keys are the official standard, many media players and tagging tools fail to handle multiple instances of the same field correctly. Some applications read only the first occurrence, while others read only the last, causing contributing artists to disappear from library views.

To overcome these software limitations, several alternative conventions have emerged:

  1. Text Delimiters: Some software writes multiple artists into a single string separated by delimiters like semicolons (ARTIST=Alice; Bob), slashes (ARTIST=Alice / Bob), or null characters (\0). When read by advanced players, these strings are split back into separate entries, though this behavior is not standardized by Xiph.Org.
  2. Display Titles: To preserve correct visual presentation, some workflows set a single ARTIST tag to reflect the colloquial credit (e.g., ARTIST=Alice feat. Bob) and store machine-readable multi-artist lists in auxiliary tags like ARTISTS (a multi-value convention popularized by MusicBrainz).

Best Practices for Tagging Collaborations

To ensure maximum compatibility across both standard-compliant and legacy software:

  • Use Repeated Keys for Native Formats: When using taggers like MusicBrainz Picard, Mp3tag, or Foobar2000, enable multi-value tagging to write discrete ARTIST fields according to the official Vorbis specification.
  • Always Populate ALBUMARTIST: Include a single, consistent ALBUMARTIST across all tracks on an album to prevent multi-artist tracks from splitting a single album into multiple fragmented entries in basic players.
  • Avoid Hardcoded Editorial Strings in the Artist Tag: Whenever possible, avoid formatting tags as Artist A & Artist B or Artist A feat. Artist B in the primary ARTIST field, as this treats the collaborative phrase as an entirely new artist identity rather than linking the track to the respective individuals.
