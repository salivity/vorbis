Vorbis Identification Header Packet Parameters

The Vorbis identification header is the initial configuration packet required to decode an Ogg Vorbis audio stream. This packet establishes the baseline decoding environment by defining critical stream attributes such as audio channels, sample rate, suggested bitrates, window sizes, and stream integrity markers. Without successfully parsing this header, a decoder cannot interpret the subsequent setup data or compressed audio payloads.

Packet Type and Codec Identifier

  • Packet Type (8 bits): An 8-bit value that must be set to 0x01 to denote an identification header.
  • Identifier Pattern (48 bits): The continuous 6-byte ASCII string "vorbis" (represented in hexadecimal as 0x76, 0x6F, 0x72, 0x62, 0x69, 0x73). This confirms the bitstream format.

Core Audio Parameters

  • Vorbis Version (32 bits): An unsigned 32-bit integer indicating the Vorbis version. In the current specification, this value must always be 0.
  • Audio Channels (8 bits): An unsigned 8-bit integer specifying the number of channels. This value must be greater than zero (for example, 1 for mono or 2 for stereo).
  • Audio Sample Rate (32 bits): An unsigned 32-bit integer indicating the sampling rate in Hertz (such as 44100 or 48000). This value must be greater than zero.

Bitrate Management Fields

  • Bitrate Maximum (32 bits): A signed 32-bit integer indicating the maximum allowed bitrate in bits per second. If this constraint is unspecified or unused, it is set to 0 or treated as a negative/null limit depending on decoder implementation.
  • Bitrate Nominal (32 bits): A signed 32-bit integer representing the preferred or nominal bitrate in bits per second. A value of 0 indicates that the encoder did not specify a target bitrate (common in variable bitrate encoding).
  • Bitrate Minimum (32 bits): A signed 32-bit integer indicating the minimum allowed bitrate in bits per second. A value of 0 signifies no minimum constraint.

Block Sizes and Framing

  • Blocksize 0 (4 bits): An unsigned 4-bit integer representing the exponent \(n\) used to calculate the short transform window size as \(2^n\). Valid values range from 6 (64 samples) to 13 (8192 samples).
  • Blocksize 1 (4 bits): An unsigned 4-bit integer representing the exponent \(n\) used to calculate the long transform window size as \(2^n\). Valid values also range from 6 to 13, with the requirement that blocksize_0 must be less than or equal to blocksize_1.
  • Framing Flag (1 bit): A single bit that must be non-zero (1). It functions as an integrity check to verify that the identification header has unpacked correctly and is properly synchronized.
