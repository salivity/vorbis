How Tremor Uses Fixed-Point Math in Vorbis Decoding

Tremor, officially known as libvorbisidec, is an integer-only implementation of the Xiph.Org Vorbis audio decoder engineered specifically for embedded hardware lacking dedicated floating-point units (FPUs). By substituting standard IEEE 754 single- and double-precision floating-point operations with deterministic 32-bit and 64-bit fixed-point arithmetic, Tremor enables efficient playback of Ogg Vorbis audio on low-power microcontrollers and digital signal processors (DSPs). This conversion relies on custom fractional number formats, trigonometric lookup tables, block floating-point strategies, and platform-specific integer multiplication optimizations.

Q-Format and Fractional Integer Representation

The standard reference decoder (libvorbis) processes spectral data, window coefficients, and synthesis vectors using native floating-point numbers. Tremor replaces these with signed integers using implicit fractional scaling, predominantly adhering to various Q-format conventions (such as Q15 or Q31).

In this representation, a fixed number of bits are allocated to the integer portion and the remaining bits to the fractional value. For example, a 32-bit integer in Q31 format treats the most significant bit as the sign bit and the remaining 31 bits as fractional values between -1.0 and +1.0. Multiplication between two Q31 numbers produces a 64-bit result that is shifted right by 31 bits to restore the original scale, eliminating the need for floating-point calculation cycles.

Inverse MDCT (IMDCT) Transformation

The most computationally intensive stage of Vorbis decoding is the Inverse Modified Discrete Cosine Transform (IMDCT), which converts frequency-domain spectral coefficients into time-domain pulse-code modulation (PCM) samples.

Tremor modifies the IMDCT pipeline through the following mechanisms:

  • Integer Trigonometric Tables: Instead of generating runtime sine and cosine values using floating-point math, Tremor relies on precomputed lookup tables populated with scaled 32-bit integer values.
  • Scaled Butterfly Operations: Butterfly stages are redesigned using integer multiply-accumulate (MAC) routines. Bit-shifts are selectively applied between stages to prevent intermediate values from overflowing 32-bit registers while preserving numerical precision.
  • Windowing Overlap-Add: The synthesis windowing step multiplies decoded samples by a standard Vorbis window function. Tremor stores this window as a lookup table of fixed-point scalars, multiplying them against the IMDCT output and shifting down to 16-bit signed PCM audio.

Floor Curve Synthesis and Dynamic Range

Vorbis encodes spectral envelopes using "Floor" structures (Floor 0 and Floor 1). Floor 1 uses line-segment interpolation in a non-linear, Bark-scale frequency space.

While the reference implementation calculates slope and amplitude curves with floating-point linear interpolation and exponential mapping, Tremor handles this using integer-only algorithms:

  • Bresenham-Style Line Interpolation: Tremor computes the line segments between floor keypoints using integer error-accumulation techniques, similar to classic computer graphics line-drawing algorithms.
  • Integer Exponentiation: Converting dB-scale floor curves into linear energy multipliers typically requires calculating \(2^x\) or \(10^x\). Tremor computes these values using lookup tables combined with bitwise shifting to manage the integer mantissa and exponent separately.

Codebook Vector Quantization (VQ)

Vorbis residual spectra are decoded through vector quantization codebooks. In the floating-point reference decoder, codebook values are represented as floats, and vector reconstruction involves scalar floating-point multiplications.

Tremor stores codebook entries as compact integers paired with dynamic scaling factors. Multiplications against the floor curve are deferred or combined into single-pass integer operations, reducing intermediate quantization noise and preserving headroom across large dynamic ranges.

Headroom Management and Overflow Prevention

Floating-point numbers inherently prevent clipping through a wide, dynamic exponent range. In contrast, fixed-point math is prone to overflow if values grow too large, or underflow (quantization noise) if values grow too small.

To mitigate this, Tremor applies a block floating-point technique to critical decoder stages. An entire block of spectral coefficients shares a common dynamic scale factor (exponent). Before executing transforms like the IMDCT, the algorithm inspects the maximum amplitude within the block, dynamically normalizes the data to maximize register usage, and tracks the shift count. After the transform is complete, the samples are denormalized using a final arithmetic right shift.

Architecture-Specific Multipliers

Tremor includes architecture-specific assembly routines for platforms such as ARM, MIPS, and x86. These routines take advantage of native 32-bit by 32-bit multiplications that yield 64-bit results (long long in C). By computing the 64-bit intermediate result directly in hardware registers and extracting the upper bits via inline assembly instructions, Tremor completely circumvents slow software-emulated 64-bit math libraries.
