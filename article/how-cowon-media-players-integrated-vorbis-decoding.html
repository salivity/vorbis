How Cowon Media Players Integrated Vorbis Decoding

This article examines how Cowon Systems integrated native Ogg Vorbis decoding into its portable media players during the early to mid-2000s. By moving away from fixed-function audio chips and adopting programmable digital signal processor (DSP) system-on-chips—principally from Telechips—Cowon implemented fixed-point decoding firmware based on Xiph.Org's Tremor library. This architecture allowed devices like the iAUDIO series to process complex, variable bitrate Vorbis streams directly on hardware with minimal battery impact and without host CPU bottlenecks.

Transition to Programmable DSP Architectures

Early portable MP3 players relied on Application-Specific Integrated Circuits (ASICs) designed exclusively to decode MPEG-1 Audio Layer III audio. These chips lacked the flexibility to process different compression algorithms. To support open-source and computationally demanding formats like Ogg Vorbis, Cowon shifted its hardware design to System-on-Chips (SoCs) equipped with programmable DSP cores and RISC microcontrollers, most notably the Telechips TCC series (such as the TCC730, TCC760, and TCC770).

These chipsets split duties between a general-purpose processor (often an ARM core) handling user interface, file system navigation, and peripheral management, and a dedicated programmable audio DSP executing the audio decoding pipelines. Because the DSP was instruction-programmable, it could be reconfigured via firmware updates to execute entirely new decoding routines.

Implementing Fixed-Point Decoding with Tremor

The standard reference implementation for Ogg Vorbis, libvorbis, required floating-point arithmetic. Early portable processors and low-power audio DSPs lacked dedicated hardware Floating-Point Units (FPUs) due to power and die-size constraints. Emulating floating-point operations in software was too slow and consumed excessive battery life.

Cowon bypassed this limitation by incorporating Xiph.Org’s Tremor (libvorbisidec) library into their firmware builds. Released in late 2002, Tremor was an integer-only, fixed-point implementation of the Vorbis specification. Cowon’s engineering team adapted this fixed-point math to match the native word sizes and register architectures of their chosen DSPs, enabling real-time playback of high-bitrate Ogg files (up to Q10 quality) without causing buffer underruns.

Microcode Optimization and Memory Management

Integrating Vorbis into portable hardware required addressing strict memory and memory-bandwidth limitations. Vorbis decoding requires significant RAM for bitstream unpack buffers, Huffman tree storage, and Modified Discrete Cosine Transform (MDCT) calculations.

Cowon optimized the decoding pipeline in several key ways:

  • DSP Assembly Optimization: Critical mathematical inner loops, specifically the Inverse MDCT (IMDCT) and windowing stages, were hand-optimized using DSP assembly instructions to leverage single-cycle Multiply-Accumulate (MAC) hardware.
  • SRAM Buffer Allocation: Dynamic memory allocation was replaced with static buffers carefully mapped to internal, high-speed on-chip SRAM to prevent cache misses and bus contention.
  • Direct Memory Access (DMA) Pipelining: Raw Ogg bitstreams were transferred from internal flash storage or microdrives to the decoding buffers using DMA controllers, freeing the main CPU core to enter low-power sleep states during active playback.

Hardware-Accelerated Audio Filtering

Once the DSP core unpacked the bitstream and computed the PCM samples, Cowon routed the raw audio through proprietary post-processing routines, such as BBE, Mach3Bass, and multi-band parametric equalization (collectively branded as JetEffect). Because the core decoding ran natively within the DSP environment, these complex audio enhancement filters could be applied directly to the decompressed PCM stream in hardware before digital-to-analog conversion, avoiding quantization noise and maintaining low latency.
