Ogg Page Header Structure for Vorbis Audio

This article breaks down the binary structure of an Ogg page header encapsulating Vorbis audio data. It covers the mandatory 27-byte fixed header, the variable segment table, and the specific rules governing how Vorbis audio packets, timestamps (granule positions), and stream states are represented within the Ogg transport framing.

The Ogg Page Format Overview

The Ogg container is a stream-oriented container designed to multiplex and interleave multimedia data. Vorbis raw audio packets are segmented and wrapped into sequential "pages." Every Ogg page begins with a 27-byte fixed header, followed by a dynamic segment table, which is then immediately followed by the payload data containing the Vorbis bitstream.

Fixed Header Fields (27 Bytes)

The fixed-size portion of an Ogg page header contains eight fields arranged in the following layout:

Field Name Size Offset Description
Capture Pattern 4 bytes 0 ASCII string OggS (0x4F 0x67 0x67 0x53). Used for page frame synchronization.
Stream Structure Version 1 byte 4 Currently defined as 0x00. Indicates the Ogg format version.
Header Type Flag 1 byte 5 Bitfield indicating stream status (detailed below).
Granule Position 8 bytes 6 A 64-bit little-endian integer used for timeline mapping and seeking.
Bitstream Serial Number 4 bytes 14 A 32-bit unique identifier for the specific Vorbis logical bitstream.
Page Sequence Number 4 bytes 18 A 32-bit monotonically increasing sequence number per logical stream.
Checksum (CRC32) 4 bytes 22 A 32-bit CRC covering the entire page (header with CRC field zeroed, plus payload).
Page Segments 1 byte 26 An unsigned integer (\(N\), from 0 to 255) defining the size of the segment table.

Header Type Flags

Byte 5 contains bitwise flags that signify boundaries within the bitstream:

  • 0x01 (Continuation): The first packet on this page is a continuation of an unfinished packet from the previous page.
  • 0x02 (Beginning of Stream - BOS): Indicates this is the very first page of the logical bitstream. For Vorbis, this page contains the Vorbis identification header.
  • 0x04 (End of Stream - EOS): Indicates this is the final page of the logical bitstream.

Combinations are permitted; for example, a short single-page stream can have both 0x02 and 0x04 set.

Granule Position in Vorbis

The 64-bit Granule Position represents the precise playback sample position of the stream:

  • In Vorbis, it designates the total number of decoded audio samples (PCM frames) up to and including the end of the final completed packet on that page.
  • If a page contains only partial packets that span into future pages without completing any packet, the granule position is set to -1 (all bits set to 0xFF).
  • For the initial Vorbis header packets (Identification, Comment, and Setup), the granule position is set to 0.

The Dynamic Segment Table (Lacing Values)

Directly following byte 26 is the segment table, which has a length equal to the value in the Page Segments field (0 to 255 bytes). Each byte represents the length of a payload segment (0 to 255 bytes).

The Ogg format uses these "lacing values" to package variable-length Vorbis packets:

  • Segment Length < 255: Marks the termination of a Vorbis packet. The byte's value is the exact length of that final segment.
  • Segment Length == 255: Indicates that the packet continues into the next segment.

Packet Sizing Example:

  • A Vorbis packet of 600 bytes is represented by three lacing values: 255, 255, and 90 (\(255 + 255 + 90 = 600\)).
  • A Vorbis packet of exactly 510 bytes is represented by: 255, 255, and 0 (the trailing 0 explicitly terminates the packet).

The total payload size of the page is the mathematical sum of all entries in the segment table. The maximum data payload for a single Ogg page is \(255 \times 255 = 65,025\) bytes.

Vorbis Initialization Sequence

When encapsulating Vorbis, three specific header packets must appear at the beginning of the bitstream before any raw audio pages:

  1. Identification Header: Encapsulated in the initial page marked with the BOS flag (0x02). It defines audio parameters such as sample rate, channel count, and Vorbis version.
  2. Comment Header: Contains user metadata, track details, and vendor strings.
  3. Setup Header: Contains codebooks and floor/residue mapping configurations necessary for decoding the audio packets.

Following these headers, all subsequent pages carry standard audio data packets, updating the granule position sequentially to track audio playback.
