Identify Vorbis vs Theora in Ogg Containers

A media parser distinguishes between Vorbis audio and Theora video inside an Ogg container by inspecting the initial packet contained within each logical stream's Beginning of Stream (BOS) page. Because Ogg is a multiplexing container, individual media tracks exist as separate logical bitstreams with unique serial numbers. By reading the distinct magic bytes located at the beginning of each stream's identification header, a parser can determine the codec type and initialize the correct decoding pipeline.

The Role of the BOS Page

Every logical bitstream inside an Ogg file begins with a mandatory header page marked by the Beginning of Stream (BOS) flag. When an Ogg page is read, the parser checks the header_type_flag field (located at byte offset 5 of the 27-byte Ogg page header). If bit 0x02 is set, the page represents the start of a new logical stream.

An Ogg parser must read the payload of this BOS page, which contains the codec-specific identification header. The first few bytes of this payload serve as a magic number that defines the stream format.

Identifying Vorbis Audio

An Ogg Vorbis stream requires three setup packets, the first of which is the identification header found directly in the BOS page.

The parser validates a Vorbis stream by reading the first 7 bytes of the packet payload:

  • Byte 0: 0x01 (Packet type flag representing the identification packet)
  • Bytes 1–6: 0x76 0x6F 0x72 0x62 0x69 0x73 (The ASCII string "vorbis")

If the first 7 bytes match \x01vorbis, the stream is parsed as Vorbis. The following bytes in this packet provide essential stream properties, such as the Vorbis version, number of audio channels, sample rate, and target bitrates.

Identifying Theora Video

Similar to Vorbis, Theora uses a series of three header packets beginning with an identification header in its BOS page.

The parser identifies a Theora stream by inspecting the first 7 bytes of the packet payload:

  • Byte 0: 0x80 (Packet type flag representing the identification packet)
  • Bytes 1–6: 0x74 0x68 0x65 0x6F 0x72 0x61 (The ASCII string "theora")

If the first 7 bytes match \x80theora, the stream is identified as Theora. The remaining bytes of the identification packet contain video metadata, including major/minor/sub-minor version numbers, frame width and height in macroblocks, pixel aspect ratio, frame rate, and color space information.

Parsing Workflow

To reliably demux an .ogg file containing both audio and video, a parser executes the following sequence:

  1. Read the physical Ogg pages from the start of the file.
  2. Check if the page has the BOS flag set (header_type_flag & 0x02 != 0).
  3. Extract the initial packet from the BOS page segment table.
  4. Read the first 7 bytes of the packet:
    • Match against \x01vorbis to register the stream's serial number as Vorbis audio.
    • Match against \x80theora to register the stream's serial number as Theora video.
  5. Map the 4-byte logical bitstream serial number (bytes 14–17 of the Ogg page header) to the detected codec.
  6. Continue parsing subsequent pages, routing packet payloads to their respective decoders based on the serial number matched during identification.
