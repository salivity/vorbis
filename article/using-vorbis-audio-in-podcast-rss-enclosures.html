Using Vorbis Audio in Podcast RSS Enclosures

Podcast RSS feeds handle Vorbis audio files through standard enclosure tags, relying on specific MIME types to deliver the media to podcast directories and listening apps. While the RSS 2.0 specification natively accommodates Vorbis by linking to the file's URL and declaring its media type, real-world handling depends heavily on client-side support. This article explains how Vorbis enclosures are structured in RSS XML, the correct MIME types to use, and how major podcast platforms process them.

The Structure of a Vorbis RSS Enclosure

In an RSS 2.0 feed, audio episodes are embedded within an <item> block using the <enclosure> tag. The tag requires three attributes: url, length (file size in bytes), and type (the MIME type).

A standard enclosure pointing to a Vorbis audio file inside an Ogg container is formatted as follows:

<enclosure 
  url="https://example.com/episodes/episode1.ogg" 
  length="42456789" 
  type="audio/ogg" />

As long as the XML syntax is valid, the feed parser will read the Vorbis file like any other media asset. The RSS protocol itself is format-agnostic and does not restrict the types of audio files linked in an enclosure.

Correct MIME Types for Vorbis

Using the correct MIME type is essential so listening clients understand how to decode the audio stream before downloading it. For Vorbis files, the standard container format is Ogg.

  • audio/ogg: The standard, recommended MIME type defined by RFC 5334 for audio-only Ogg Vorbis files.
  • application/ogg: A legacy or general MIME type. While technically valid, some podcast aggregators may fail to recognize it as a playable audio file.
  • audio/vorbis: Occasionally used in experimental setups, but largely unsupported by mainstream RSS readers.

Podcasters publishing Vorbis audio should use the .ogg or .oga file extension paired with the audio/ogg MIME type attribute to maximize compatibility.

Platform Support and Limitations

Although an RSS feed can easily declare a Vorbis enclosure, ecosystem-wide playback compatibility remains limited:

  • Apple Podcasts: Apple enforces strict media requirements for its directory. Apple Podcasts does not support Ogg Vorbis enclosures natively. Feeds submitted to Apple Podcasts with Vorbis enclosures will generally fail validation or result in unplayable episodes.
  • Spotify: While Spotify uses Ogg Vorbis internally for its own streaming delivery, its podcast ingestion specifications strongly mandate MP3 or M4A formats for RSS enclosures. Feeds relying purely on Vorbis are typically rejected during directory submission.
  • Open-Source and Independent Clients: Apps such as AntennaPod, VLC, and many web-based feed readers fully support Ogg Vorbis playback. These clients leverage Android's native media framework or bundled open-source decoders to stream or download Vorbis enclosures without issue.

Delivery Best Practices

Because the RSS specification allows only one <enclosure> tag per <item>, publishers cannot natively provide an MP3 fallback alongside a Vorbis file in a single episode entry.

Publishers who prefer using open-source audio formats like Vorbis typically create dual-feed setups: one primary feed encoded in MP3 or AAC for distribution to mainstream directories like Apple Podcasts and Spotify, and a secondary feed featuring Vorbis enclosures for open-source apps and users who explicitly prioritize unencumbered, patent-free codecs.
