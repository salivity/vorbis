Vorbis Setup Header Packet Identifier

This article explains the packet structure of the Vorbis audio codec, focusing specifically on the identifying string and byte sequence used to distinguish the setup configuration header. Readers will learn the exact byte representation of this identifier, how it fits into the three mandatory Vorbis header packets, and how audio decoders parse it to initialize decoding parameters.

The Setup Header Identifier

The Vorbis setup configuration header packet is identified by the 7-byte sequence \x05vorbis.

This sequence consists of:

  • A single leading byte containing the packet type integer 0x05 (indicating the setup header).
  • A 6-character ASCII string: "vorbis" (in hexadecimal: 0x76 0x6F 0x72 0x62 0x69 0x73).

In standard Vorbis bitstream framing, any packet starting with byte 0x05 followed immediately by the ASCII characters v, o, r, b, i, and s is designated as the setup header.

Vorbis Header Packet Structure

The Vorbis bitstream specification mandates three distinct header packets that must appear at the beginning of an audio stream in strict sequential order. Each header uses the same 6-character "vorbis" magic string, distinguished only by the first 1-byte packet type flag:

  1. Identification Header: Starts with \x01vorbis (0x01 followed by "vorbis"). It defines general audio parameters including the sample rate, channel count, and bitstream version.
  2. Comment Header: Starts with \x03vorbis (0x03 followed by "vorbis"). It holds metadata, such as artist, track title, and encoding tool information.
  3. Setup Header: Starts with \x05vorbis (0x05 followed by "vorbis"). It contains the structural decoding configurations.

Role of the Setup Configuration Header

The setup header is typically the largest of the three initial packets. It supplies the decoder with the codebooks, time-domain transforms, floor configurations, residue definitions, channel mappings, and playback modes required to decompress the subsequent raw audio data packets.

When an audio parser or decoder encounters the \x05vorbis signature, it verifies the stream integrity. If the leading byte is not 0x05 or the subsequent bytes fail to match "vorbis", the decoder rejects the stream as corrupt or non-compliant.
