How Encoders Identify in Vorbis Vendor Tags

In the Ogg Vorbis audio architecture, encoders identify themselves through a mandatory, dedicated field within the Vorbis comment header known as the vendor string. Unlike arbitrary user metadata tags, this vendor string is a hardcoded protocol-level identifier written directly by the encoding library during the file creation process. This article details the binary structure of the Vorbis vendor tag, the conventions encoders use to format their identity, and how decoders distinguish this field from standard user comments.

The Structure of the Vorbis Comment Header

The Vorbis comment specification defines a structured packet that stores metadata for Vorbis audio streams. The packet layout does not begin with user-defined tags like artist or track title. Instead, it strictly enforces the following sequence:

  1. A 32-bit unsigned integer representing the length of the vendor string in bytes (encoded in little-endian format).
  2. The vendor string itself, encoded in UTF-8, matching the exact length specified by the preceding integer.
  3. A 32-bit unsigned integer representing the number of user comment fields.
  4. The array of user comment fields (formatted as KEY=VALUE pairs).

Because the vendor string is stored as an independent data field rather than a KEY=VALUE pair, it is structurally distinct from common tags like ARTIST or GENRE.

How Encoders Populate the Vendor String

When an encoding library initializes an audio stream, it automatically writes its own identification string into this field. Encoders do not expose this string to standard end-user tag editing, as it is designed to reflect the software that generated the bitstream.

The convention established by Xiph.Org dictates that the string should contain the name of the library, the library version, and often a build or release date. Common examples include:

  • Reference Xiph Encoder: Xiph.Org libVorbis I 20200704 (Everywhere)
  • aoTuV Modified Encoder: aoTuV b6.03 (2020)
  • FFmpeg / Libav: Lavf59.27.100

Third-party applications or audio converters that rely on shared libraries (such as libvorbisenc) will typically inherit and write the vendor string of the underlying library rather than the name of the frontend software.

Distinguishing Vendor Tags from User Tags

Standard metadata editors frequently confuse users by displaying encoder information under user tags such as ENCODER or ENCODED_BY. However, these are optional user comments appended after the vendor field.

The vendor tag serves a functional role beyond mere labeling. Decoders and media players read the raw vendor string to identify the specific codec implementation that produced the stream. This allows player software to detect known encoder bugs, apply stream-correcting heuristics, or gather playback telemetry without relying on mutable user metadata.
