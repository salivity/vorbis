How Tremor Implements Trigonometry Without an FPU

The Tremor decoder (libvorbisidec) decodes Ogg Vorbis audio on platforms lacking hardware floating-point units (FPUs) by substituting floating-point arithmetic with integer-based fixed-point math. Audio decompression algorithms like Vorbis rely heavily on trigonometric functions—specifically sine and cosine—to perform the Inverse Modified Discrete Cosine Transform (IMDCT). Tremor bypasses standard runtime trigonometric libraries by utilizing precalculated lookup tables, quadrant symmetry, algorithmic transforms, and precise bit-shift operations to perform all necessary computations within standard integer registers.

Fixed-Point Representation

Standard Vorbis decoders represent audio waveforms and transformation coefficients as IEEE 754 floating-point values. Tremor represents fractional real numbers as scaled integers, primarily using Q-format arithmetic (such as Q31, where a 32-bit signed integer allocates 1 sign bit and 31 fractional bits). In this format:

  • A trigonometric value of 1.0 is represented as the maximum integer value (\(2^{31}-1\)).
  • A value of 0.0 is 0.
  • A value of -1.0 is \(-2^{31}\).

This integer scaling allows the processor's standard Arithmetic Logic Unit (ALU) to handle fractions natively without an FPU.

Precomputed Lookup Tables (LUTs)

Runtime evaluation of trigonometric functions via Taylor series or polynomial approximations (like Chebyshev polynomials) is computationally prohibitive on low-power integer hardware. Tremor completely avoids calculating trigonometric functions on the fly.

Instead, it relies on static, precomputed lookup tables embedded directly in the source code. These tables contain fixed-point representations of the exact twiddle factors (sine and cosine phase factors) required during the IMDCT and spectral synthesis stages.

Symmetry and Memory Optimization

Storing every required sine and cosine value would consume excessive ROM and cache, which are strictly limited on embedded targets. Tremor minimizes table sizes by leveraging fundamental trigonometric identities:

  • Quarter-Wave Symmetry: Since \(\cos(\theta) = \sin(\frac{\pi}{2} - \theta)\) and values repeat symmetrically across the four quadrants of a circle, Tremor only stores values for a fraction of the circle (typically one quadrant or octant).
  • Sign Inversion: Negative values and reflections across axes are resolved via simple two's-complement negation and index offsets rather than dedicated table entries.

IMDCT Reduction and FFT Folding

The most computationally intensive trigonometric operation in Vorbis is the IMDCT, which maps frequency spectrum data back into time-domain audio samples.

Rather than computing the \(N\)-point IMDCT directly—which would require an \(O(N^2)\) number of trigonometric multiplications—Tremor reformulates the IMDCT into an \(N/4\)-point complex Fast Fourier Transform (FFT). This algorithmic reduction drastically shrinks the quantity of unique angles required, reducing both table memory requirements and the total number of integer multiplications needed per audio frame.

64-Bit Accumulation and Scaling

Multiplying two 32-bit fixed-point numbers (such as an audio sample by a sine factor) yields a 64-bit intermediate product. Tremor manages this through specialized macros and inline assembly instructions optimized for targets like ARM (e.g., SMULL or SMLAL instructions) and MIPS.

After multiplication, the result is shifted right by the fractional bit depth (such as 31 bits) to normalize the value back into a 32-bit register. Tremor carefully stages these scaling shifts throughout the transform pipeline to maintain maximum dynamic range while preventing integer overflow and minimizing quantization noise.
