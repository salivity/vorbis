Vorbis Framing in an Ogg Physical Page

This article explains how the Vorbis audio codec packages and frames its compressed audio data inside the physical pages of an Ogg container. Because raw Vorbis streams lack internal framing mechanisms such as synchronization words or packet length headers, the format relies entirely on the underlying Ogg transport layer. Below is a breakdown of how Vorbis packets are divided, mapped onto the Ogg page segment table using lacing values, spanned across multiple pages, and assigned time markers.

Separation of Codec and Container

Vorbis generates variable-length bitstream packets containing compressed frequency-domain audio. The Vorbis specification intentionally omits packet boundaries, framing bits, error detection, and timestamping from the raw codec layer. Instead, it delegates these responsibilities to the Ogg encapsulation layer. An Ogg physical page acts as the framing unit, providing structural synchronization, sequence verification, error detection via CRC checksums, and time synchronization.

The Ogg Physical Page Structure

An Ogg bitstream is divided into distinct physical pages, typically ranging between 4 KB and 8 KB (with an absolute maximum size of approximately 65 KB). Each page begins with a 27-byte capture header:

  • Capture Pattern: The 4-byte sequence OggS (ASCII 0x4F 0x67 0x67 0x53), allowing decoders to synchronize with page boundaries.
  • Header Type Flag: Identifies whether the page is continued from a previous page, represents the start of a logical bitstream (bos), or marks the end of a bitstream (eos).
  • Granule Position: A 64-bit integer representing the exact audio sample position of the end of the last complete packet on the page, used by Vorbis for seeking and playback timing.
  • Stream Serial Number and Page Sequence Number: Identify multiplexed streams and detect lost or out-of-order pages.
  • Checksum: A 32-bit CRC covering the entire page header and payload.
  • Page Segments Counter: An 8-bit unsigned integer (0 to 255) defining the number of entries in the subsequent segment table.

The Segment Table and Lacing Values

The mechanism directly responsible for framing Vorbis packets within the page is the segment table, which immediately follows the fixed header.

Vorbis packets are sliced into segments of up to 255 bytes. The length of each segment is stored as an 8-bit lacing value (ranging from 0 to 255) in the segment table:

  1. Intermediate Segments: Any segment of exactly 255 bytes is recorded with a lacing value of 255, indicating that the current Vorbis packet continues into the next segment.
  2. Terminal Segments: A segment of less than 255 bytes (from 0 to 254) terminates the Vorbis packet.

For example, a Vorbis packet of 600 bytes is represented in the segment table by three lacing values: 255, 255, and 90 (255 + 255 + 90 = 600). A packet that happens to be an exact multiple of 255 bytes (such as 510 bytes) is represented by 255, 255, and 0, where the final 0 explicitly indicates the boundary of the packet.

By reading the segment table sequentially, the decoder can reconstruct the boundaries and lengths of multiple Vorbis packets residing in the page payload without needing internal codec markers.

Packet Spanning Across Page Boundaries

A single Vorbis packet can span across multiple Ogg pages if the packet is larger than the remaining capacity of the current page.

  • Page Overflow: When a page reaches its maximum segment count (255 entries) or maximum size while encoding a Vorbis packet, the segment table on that page will end with a lacing value of 255.
  • Continuation Flag: The next sequential Ogg page sets the continuation flag (bit 0x01 in the header type byte). This alerts the Vorbis decoder that the first payload byte of the new page is not the start of a new packet, but rather a direct continuation of the unfinished packet from the preceding page.

Reconstruction by the Decoder

When reading the physical bitstream, the Vorbis decoder:

  1. Locates the OggS sync pattern and validates the page checksum.
  2. Reads the segment table to identify individual packet boundaries.
  3. Assembles the segments belonging to each packet into a contiguous byte buffer.
  4. Passes the complete, framed packet to the Vorbis synthesis engine for audio decoding.
  5. Uses the page's granule position to verify time alignment and manage sample-accurate seeking.
