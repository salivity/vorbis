Vorbis Comment Vendor String Structure Explained

The Vorbis comment vendor string is a mandatory metadata field located at the beginning of a Vorbis comment header, used across container formats like Ogg, FLAC, and Opus to identify the encoding software or library. This article breaks down the binary layout of the vendor string, its byte order, encoding standards, and how decoders read this data.

Binary Layout of the Vendor String

The Vorbis comment specification places the vendor string immediately at the start of the comment payload (after any format-specific packet headers, such as the Vorbis comment packet type flag). The vendor string structure consists of two consecutive fields:

  1. Vendor Length Field (32 bits / 4 bytes): An unsigned 32-bit integer stored in little-endian byte order. This value specifies the exact length of the vendor string in bytes, not in characters.

  2. Vendor String Data (Variable length): A continuous sequence of bytes of the size specified by the length field. The content is encoded in human-readable UTF-8 format.

Field Size Data Type Description
Length 4 bytes 32-bit Unsigned Int (Little-Endian) The size of the vendor string in bytes (\(N\))
String \(N\) bytes UTF-8 String The vendor identifier data (not null-terminated)

Key Technical Characteristics

  • Little-Endian Ordering: When reading the 4-byte length field, the bytes must be parsed from least significant byte to most significant byte (LSB to MSB). For example, a length of 14 bytes is stored as the hex sequence 0E 00 00 00.
  • No Null Termination: Unlike standard C-style strings, the vendor string is not null-terminated with a 0x00 byte. Parsers must rely strictly on the 32-bit length prefix to determine where the string ends. If a null byte is encountered, it is treated as part of the data.
  • Byte Count vs. Character Count: Because the string is UTF-8 encoded, multi-byte characters consume multiple bytes. The 32-bit length integer always defines the total count of octets (bytes), not the number of Unicode code points.

Standard Contents and Usage

The content of the vendor string is determined by the encoder that generated the stream. By convention, it contains the name of the library and often a version number or release date.

Common real-world examples include:

  • Xiph.Org libVorbis I 20200704 (Everywhere)
  • Lavf59.27.100 (FFmpeg Libavformat)
  • reference libFLAC 1.4.2 20221022

Immediately following the final byte of the vendor string, the Vorbis comment block proceeds directly to the user comment count, which is another 32-bit little-endian integer defining how many KEY=VALUE metadata tags follow.
