Vorbis Identification Header Bitstream Structure

This article provides a technical overview of the Vorbis identification header, detailing the exact bitstream layout and field requirements necessary to initialize a Vorbis audio decoder. It examines the packet's sequential byte structure, including the initial packet type, codec identifier, audio configuration parameters, bitrate limits, block size definitions, and the trailing framing bit.

Overview of the Identification Header

A Vorbis audio stream begins with three consecutive header packets: the identification header, the comment header, and the setup header. The identification header is the very first packet in the bitstream. It contains fundamental decode parameters such as sample rate, channel count, and internal block sizing. The packet is exactly 30 bytes (240 bits) long. All multi-byte integers are stored in little-endian byte order.

Field-by-Field Bitstream Structure

The 30-byte identification packet consists of the following sequential fields:

1. Packet Type (8 bits)

  • Size: 1 byte (unsigned integer)
  • Value: 0x01
  • Description: Identifies the packet as an identification header. In Vorbis, header packets use odd values, and 0x01 is reserved strictly for this primary identification block.

2. Codec Identifier (48 bits)

  • Size: 6 bytes (ASCII string)
  • Value: 0x76, 0x6F, 0x72, 0x62, 0x69, 0x73 ("vorbis")
  • Description: A fixed continuous sequence verifying that the stream is Vorbis audio.

3. Vorbis Version (32 bits)

  • Size: 4 bytes (unsigned integer, little-endian)
  • Value: 0x00000000 (Version 0)
  • Description: Represents the Vorbis bitstream version. Decoders must reject streams where this field does not equal zero.

4. Audio Channels (8 bits)

  • Size: 1 byte (unsigned integer)
  • Value: Greater than zero (e.g., 1 for mono, 2 for stereo)
  • Description: Specifies the number of independent audio channels. Zero is an invalid value and marks an unparseable stream.

5. Audio Sample Rate (32 bits)

  • Size: 4 bytes (unsigned integer, little-endian)
  • Value: Greater than zero (e.g., 44100, 48000)
  • Description: The sampling frequency of the encoded audio signal expressed in Hertz (Hz).

6. Bitrate Maximum (32 bits)

  • Size: 4 bytes (signed integer, little-endian)
  • Value: Rate in bits per second, or set to 0 or -1
  • Description: Indicates the upper limit for variable bitrate (VBR) streams. If unused or unregulated, it is set to zero (or negative).

7. Bitrate Nominal (32 bits)

  • Size: 4 bytes (signed integer, little-endian)
  • Value: Rate in bits per second, or set to 0 or -1
  • Description: Indicates the targeted average bitrate for the file.

8. Bitrate Minimum (32 bits)

  • Size: 4 bytes (signed integer, little-endian)
  • Value: Rate in bits per second, or set to 0 or -1
  • Description: Indicates the lower limit for variable bitrate streams. If unused, it is set to zero (or negative).

9. Blocksize 0 and Blocksize 1 (8 bits)

  • Size: 1 byte (split into two 4-bit unsigned values)
    • Bits 0–3: blocksize_0
    • Bits 4–7: blocksize_1
  • Description: Represents the two allowed window sizes for the MDCT (Modified Discrete Cosine Transform) calculations. The values represent powers of two (\(2^n\)).
    • Valid exponent range: 6 to 13 (corresponding to window sizes of 64 to 8192 samples).
    • Constraint: blocksize_0 must be less than or equal to blocksize_1.

10. Framing Flag (8 bits)

  • Size: 1 byte (primarily a 1-bit boolean followed by 7 padding bits)
  • Value: 0x01 (Bit 0 must be 1, remaining 7 bits are zero)
  • Description: A mandatory termination check ensuring bit-level synchronization. If the low bit of this byte is zero, the packet is deemed corrupt.
