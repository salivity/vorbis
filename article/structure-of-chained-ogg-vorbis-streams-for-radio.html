Structure of Chained Ogg Vorbis Streams for Radio

Chained Ogg Vorbis streams are the backbone of modern open-standard internet radio broadcasting, allowing servers like Icecast to send continuous audio while dynamically updating track metadata and encoding parameters. This article explains the technical architecture of chained Ogg Vorbis streams, detailing how independent logical bitstreams are encapsulated, structured, and sequentially linked to deliver seamless, uninterrupted digital radio broadcasts.

The Concept of Chaining in Ogg Containers

The Ogg format is a container designed to encapsulate raw codec bitstreams into transportable units called "pages." In radio broadcasting, audio cannot be treated as a single, static file because the broadcast is infinite and constantly changing tracks, ads, and metadata.

To handle this, broadcasters use chaining. A chained Ogg stream consists of multiple distinct, self-contained "logical bitstreams" concatenated sequentially into a single "physical bitstream." When one track ends, its logical stream closes, and a new logical stream immediately begins without dropping the listener's network connection.

The Structure of an Individual Ogg Page

Every segment of data within a chained stream is packaged into an Ogg page, which ranges in size up to roughly 65 kilobytes. Each page contains a 27-byte header followed by the audio payload:

  • Capture Pattern (4 bytes): Always reads OggS (ASCII 0x4F 0x67 0x67 0x53) to establish page synchronization.
  • Stream Structure Version (1 byte): Set to 0x00.
  • Header Type Flag (1 byte): Indicates the state of the logical bitstream:
    • 0x01: Continued packet from the previous page.
    • 0x02: Beginning of Stream (BOS), marking the very first page of a logical stream.
    • 0x04: End of Stream (EOS), marking the final page of a logical stream.
  • Granule Position (8 bytes): The time marker or sample count used by players for seeking and synchronization.
  • Bitstream Serial Number (4 bytes): A unique identifier assigned to each logical stream.
  • Page Sequence Number (4 bytes): A monotonically increasing sequence to detect dropped pages.
  • Checksum (4 bytes): A 32-bit CRC checksum ensuring data integrity.
  • Segment Table: Defines the length of each packet in the payload.

The Lifecycle of a Logical Stream in a Chain

Within a continuous radio broadcast, each audio track or segment represents an independent logical stream moving through three sequential phases:

1. Stream Initialization (BOS)

The transition to a new track begins with a page flagged with the Beginning of Stream (0x02) marker. This page establishes a new, unique Bitstream Serial Number. Immediately following the BOS flag, three mandatory Vorbis header packets are transmitted:

  • Identification Header: Defines audio channels, sample rate, and nominal bitrate.
  • Comment Header (Vorbis Comments): Contains the track metadata, including artist, title, album, and broadcast details.
  • Setup Header: Delivers the technical codebooks and modes required by the decoder to decompress the incoming audio.

2. Audio Data Transmission

Following the headers, subsequent Ogg pages carry raw Vorbis audio packets. These pages carry the same serial number assigned during initialization, with incrementing page sequence numbers and advancing granule positions (sample counts).

3. Stream Termination (EOS)

When the track, jingle, or commercial ends, the final page of that segment is flagged with the End of Stream (0x04) marker. This signals to the client's decoder that the current decoding context is finished.

Transitioning Between Streams (The Chaining Mechanism)

In standard file playback, an EOS flag causes the audio player to stop. In a chained radio stream, the media player's demuxer recognizes that the transport layer remains open.

Immediately following the byte that concludes the EOS page of Track A, the stream delivers the BOS page of Track B, featuring a completely different Bitstream Serial Number. The player resets its Vorbis decoding pipeline, reads the new identification and comment headers, updates the "Now Playing" display with the new metadata, and resumes audio playback with zero audible gap or buffer underrun.

This chained structure makes Ogg Vorbis well-suited for broadcasting, as it supports dynamic bitrate changes, differing sample rates between tracks, and native, in-band metadata updates without requiring out-of-band protocols.
