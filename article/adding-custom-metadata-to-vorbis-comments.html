Adding Custom Metadata to Vorbis Comments

Users can fully attach custom metadata fields to Vorbis comments beyond the standard tags recommended by the specification. The Vorbis comment format—widely utilized in audio formats such as Ogg Vorbis, FLAC, and Opus—was intentionally engineered as a flexible, key-value system that permits arbitrary field names. This article explains how Vorbis metadata handles custom tags, the formatting rules required for implementation, and how software compatibility affects custom field usage.

How Vorbis Comments Handle Custom Metadata

Unlike metadata formats like ID3v2, which rely on strictly predefined frames, Vorbis comments use a straightforward text-based structure formatted as FIELD_NAME=value.

The official Xiph.Org specification explicitly defines only a minimal set of standard tags—such as TITLE, ARTIST, ALBUM, DATE, and TRACKNUMBER. However, the specification also states that this list is not exhaustive. Users and developers are free to define and write arbitrary field names to suit their organizational needs, such as CATALOGNUMBER, RECORDLABEL, BPM, or MIXARTIST.

Formatting Rules for Custom Tags

To ensure custom metadata complies with the Vorbis comment specification, field names must adhere to the following technical rules:

  • Character Set: Field names must contain only printable ASCII characters ranging from 0x20 through 0x7D, with the exception of the equals sign (=, 0x3D), which is reserved as the delimiter between the key and the value.
  • Case Insensitivity: Field names are case-insensitive. A field defined as my_custom_tag is treated identically to MY_CUSTOM_TAG. By community convention, field names are typically written in uppercase.
  • Value Encoding: The field value after the equals sign must be valid UTF-8 text, allowing for international character support across all custom data.
  • Repeated Fields: Vorbis comments support multi-value fields natively by repeating the key-value pair. For instance, multiple instances of ENSEMBLE=Artist A and ENSEMBLE=Artist B can be appended independently.

Software Support and Compatibility

While the file format supports arbitrary fields without corrupting the audio or metadata stream, how that data is used depends on the software reading it:

  • Tag Editors: Most dedicated audio tag editors—including Mp3tag, Foobar2000, MusicBrainz Picard, and Kid3—fully support creating, modifying, and saving user-defined Vorbis fields.
  • Media Players: Player support varies. While advanced players like Foobar2000 or music server platforms like Navidrome and Roon can be configured to read, filter, or display custom fields, simpler or mobile-based players usually ignore unrecognized metadata keys entirely.

Any non-standard tag will remain safely preserved in the file container, regardless of whether a particular media player chooses to display it.
