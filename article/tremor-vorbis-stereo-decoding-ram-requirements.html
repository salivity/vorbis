Tremor Vorbis Stereo Decoding RAM Requirements

Decoding a stereo Vorbis stream using Tremor (libvorbisidec) typically requires between 16 KB and 48 KB of dynamic RAM (heap), with an average typical consumption of around 20 KB to 30 KB for standard audio profiles. Tremor is a fixed-point version of the Vorbis reference decoder specifically engineered for resource-constrained embedded systems and microcontrollers, drastically reducing memory overhead compared to the standard floating-point libvorbis implementation.

Breakdown of Memory Usage

The exact memory required during decoding is determined by several core components of the Vorbis format and Tremor’s internal design:

  • Internal Decoder State: Tremor allocates tracking structures, floor calculation tables, codebook references, and mode configurations when the stream headers are parsed. This base footprint typically accounts for 8 KB to 12 KB of heap space.
  • Overlap-Add (PCM) Buffers: Vorbis relies on overlapping window frames to reconstruct audio. Tremor must store the synthesis window and past PCM samples across channels to blend consecutive frames. For a stereo stream using typical block sizes (e.g., long blocks of 2048 or 4096 samples), the PCM ring buffers and overlap memory consume approximately 8 KB to 16 KB.
  • Working Vector Buffers: Intermediate decode buffers used for inverse Modified Discrete Cosine Transform (iMDCT) and residue unpacking require temporary workspace. Tremor optimizes this by reusing buffers across phases, generally keeping working scratchpad requirements under 6 KB to 8 KB.
  • Bitstream and Input Buffers: The underlying Ogg bitstream parser (libogg or Tremor's integrated parser) requires an input buffer to assemble full packets. This usually requires 2 KB to 8 KB, depending on how the application supplies raw stream chunks to the decoder.

Key Factors Affecting RAM Footprint

  1. Window / Block Size: Vorbis streams use variable block sizes (short and long). Audio encoded with long block sizes of 4096 or 8192 samples requires proportionally larger windowing and overlap buffers than audio limited to 1024 or 2048 samples.
  2. Channel Count: Memory requirements scale almost linearly with channel count for the synthesis buffers. A mono stream can reduce memory usage down to roughly 12 KB to 20 KB, while standard stereo requires the typical 20 KB to 30 KB footprint.
  3. Static Allocation vs. Dynamic Heap: Default Tremor utilizes dynamic allocation (malloc and free). Embedded developers frequently patch Tremor to use static allocation or custom memory pools, locking the memory budget to a fixed ceiling (typically 32 KB to 40 KB) to prevent runtime heap fragmentation.
