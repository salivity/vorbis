Unique Mode Mappings in a Vorbis Stream

This article explains the maximum number of unique mode configurations allowed within an Ogg Vorbis audio stream. It breaks down the bitstream constraints defined in the Vorbis I specification, examines how the setup header establishes mode structures, and clarifies how packets reference these modes during audio decoding.

In a single Vorbis stream, there can be a maximum of 64 unique modes defined.

According to the Vorbis I specification, all structural decoding configurations are defined in the third header packet, known as the setup header. When parsing the setup header, the decoder reads the mode count from a 6-bit unsigned integer field and increments that value by one:

vorbis_mode_count = read(6 bits) + 1

Because a 6-bit integer can represent values from 0 to 63, the resulting vorbis_mode_count strictly ranges from 1 to 64. A Vorbis stream cannot contain zero modes, nor can it exceed 64 modes.

The Role of a Vorbis Mode

In Vorbis, a "mode" functions as the top-level template for decoding individual audio packets. Each packet begins with a bitfield indicating which mode to use for that specific frame.

Each mode structure specifies:

  • Blockflag (1 bit): Determines whether the frame uses a short window or a long window for time-domain to frequency-domain transformation.
  • Windowtype (16 bits): Defines the window shape (set to 0 in Vorbis I).
  • Transformtype (16 bits): Defines the transform type (set to 0 in Vorbis I for the Modified Discrete Cosine Transform).
  • Mapping (8 bits): Points to a specific mapping configuration index (which links channel couplings, floors, and residues).

Packet Overhead and Mode Selection

Because the setup header explicitly fixes the mode count, audio packets only need to spend the minimum number of bits required to address the active modes. The bit length for the mode index in each packet is determined by the formula:

mode_bits = ilog(vorbis_mode_count - 1)

For example, if a stream defines only 2 modes, each audio frame only requires 1 bit to signal the active mode. If a stream uses the full limit of 64 modes, each frame requires 6 bits to identify the mode.
