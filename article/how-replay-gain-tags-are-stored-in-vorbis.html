How ReplayGain Tags Are Stored in Vorbis

This article explains how ReplayGain metadata—specifically REPLAYGAIN_TRACK_GAIN and REPLAYGAIN_ALBUM_GAIN—is structured and stored within the Vorbis audio format. In Ogg Vorbis files, ReplayGain values are not saved in custom binary chunks or ID3 frames; instead, they are written as plain text key-value pairs within the native Vorbis comment metadata header block. Understanding this format is essential for properly reading, writing, and standardizing audio normalization metadata across media players and tag editors.

The Vorbis Comment Structure

Vorbis metadata is handled by the Vorbis comment specification. In this specification, metadata fields are stored as arbitrary, null-less UTF-8 strings structured as:

FIELD_NAME=Value

Field names are case-insensitive and restricted to printable ASCII characters between 0x20 and 0x7D, with the equals sign (=, 0x3D) excluded as it serves as the delimiter. While the specification treats field names without regard to case, uppercase is the universal standard for ReplayGain metadata.

Tag Formatting for Track and Album Gain

The specific field names used for volume normalization are:

  • REPLAYGAIN_TRACK_GAIN: The adjustment applied to normalize the volume of an individual track.
  • REPLAYGAIN_ALBUM_GAIN: The adjustment applied to normalize the entire album while maintaining the dynamic range differences between tracks.

Value Representation

The values for both REPLAYGAIN_TRACK_GAIN and REPLAYGAIN_ALBUM_GAIN follow strict string formatting conventions:

  1. Numeric Decibel Value: The value represents the gain adjustment in decibels (dB). It is written as a floating-point number, typically rounded to two decimal places (e.g., +1.25 or -6.40).
  2. Explicit Sign: The value must include an explicit sign: either a plus sign (+) for amplification or a minus sign (-) for attenuation.
  3. Unit Suffix: The number is followed by a space and the unit dB.

Examples

In a Vorbis comment packet, these tags appear as:

REPLAYGAIN_TRACK_GAIN=-4.52 dB
REPLAYGAIN_ALBUM_GAIN=-3.10 dB

Accompanying Peak Tags

To prevent clipping when these gain adjustments are applied, Vorbis comments frequently store companion peak values:

  • REPLAYGAIN_TRACK_PEAK
  • REPLAYGAIN_ALBUM_PEAK

Unlike the gain fields, peak values do not represent decibels; they represent the absolute peak sample value normalized where 1.0 is digital full scale (0 dBFS). These are formatted as floating-point numbers without an explicit plus sign or unit suffix (for example, REPLAYGAIN_TRACK_PEAK=0.985412).

Binary Storage Inside the Ogg Stream

At the bitstream level, the Vorbis comment header is the second header packet in an Ogg Vorbis logical stream, following the identification header. Each comment entry is stored as a 32-bit unsigned little-endian integer indicating the length of the string in bytes, immediately followed by the UTF-8 encoded KEY=VALUE string itself. ReplayGain values are embedded sequentially within this list without requiring special flags, making them easily parseable by standard Vorbis comment utilities.
