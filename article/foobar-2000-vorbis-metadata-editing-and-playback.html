Foobar2000 Vorbis Metadata Editing and Playback

Foobar2000 provides native, highly efficient handling of Ogg Vorbis files, combining bit-perfect playback with an advanced tagging engine. This article examines how the player decodes Vorbis streams, manages gapless playback and ReplayGain, and manipulates Vorbis Comments directly through its built-in metadata editing tools without altering the underlying audio data.

Vorbis Playback Architecture

Foobar2000 handles Ogg Vorbis natively using optimized decoding libraries based on official Xiph.Org specifications. The player streams the Ogg container directly, demuxing the Vorbis bitstream with minimal CPU overhead and outputting high-precision PCM data (up to 32-bit floating point) to the system audio pipeline.

Key playback features include:

  • True Gapless Playback: Vorbis introduces sample-count padding at the beginning and end of streams due to its block-based transform design. Foobar2000 reads the exact sample counts stored in the Vorbis headers, stripping priming and padding samples to ensure sample-accurate, gapless transitions between tracks.
  • ReplayGain Processing: Foobar2000 calculates and applies ReplayGain adjustments on the fly. For Vorbis files, it reads REPLAYGAIN_TRACK_GAIN, REPLAYGAIN_TRACK_PEAK, REPLAYGAIN_ALBUM_GAIN, and REPLAYGAIN_ALBUM_PEAK metadata keys. The player adjusts digital volume non-destructively during decoding without altering the original audio samples.

Vorbis Metadata Editing (Vorbis Comments)

Vorbis files use a simple, structured metadata standard called Vorbis Comments, consisting of UTF-8 encoded KEY=Value pairs. Foobar2000 interacts with these comments directly rather than trying to force an ID3 structure onto the container.

Non-Destructive Header Updates

When editing tags, Foobar2000 modifies only the comment header packet within the Ogg encapsulation. It rewrites the header block and adjusts page sequence numbers without touching the audio packets, eliminating the risk of stream corruption or generation loss.

Managing Tags via the Properties Window

Accessing the Properties dialog (via right-click or Alt + Enter) provides direct access to the metadata table:

  • Standard Fields: Standard tags like TITLE, ARTIST, ALBUM, TRACKNUMBER, and DATE are mapped automatically to user-friendly UI fields.
  • Custom and Extended Fields: Foobar2000 allows users to add arbitrary metadata fields. Any custom key entered into the properties dialog is written directly to the file as a valid Vorbis Comment field.
  • Multi-Value Fields: The Vorbis Comment format allows identical field keys (e.g., multiple GENRE or ARTIST lines). Foobar2000 natively supports this standard. In the UI, multiple values are separated by semicolons (;), which the editor then writes to the file as distinct key-value pairs.

Embedded Artwork Handling

Historically, Vorbis Comments lacked a formal mechanism for embedded cover art, leading to non-standard Base64-encoded strings. Foobar2000 adheres to modern Xiph specifications by writing embedded art using the METADATA_BLOCK_PICTURE structure. This embeds binary picture data—including MIME type, description, dimensions, and color depth—safely inside the comment header, maintaining compatibility with modern media players.

Batch Tagging and Advanced Tools

Foobar2000 includes tools that streamline Vorbis library management:

  • Automatically Fill Values: Derives metadata from folder structures and filenames using customizable syntax (e.g., %artist% - %album%\%track% - %title%).
  • Mass Tagging: Users can highlight hundreds of Vorbis tracks simultaneously to edit unified metadata, add ReplayGain tags in batches, or rename files on disk based on existing Vorbis Comments.
